# DSH 0.2.1 插件规范对齐与体验重构（2026-10-20）

## 背景

本仓库当前版本 `2.2.7` 面向 DSH `0.1.2-rc.1` 编写。当前运行环境是
DSH Desktop `0.2.1-rc.2`，两者之间插件契约发生了实质变化：

| 领域 | 2.2.7 的做法 | 0.2.1-rc.2 的现状 |
|---|---|---|
| 宿主插件形态 | 对象形态 `{ name, inject, apply }`，手写局部类型 | 命名导出 `apply` / `inject` / `Config`（函数形态），`Config` 由 Schemastery 校验 |
| 插件清单 | 只有 `dsh.bundle.patch` 与 `dsh.client.inject` | 另需 `exports["./locale/*.json"]`、`exports["./icon"]`、`files` 覆盖、`meta.title/description`、图标；版本要求经 `engines.dsh` 判定 |
| 插件目录/状态 | 猜测 `web` / `headless` profile，自己维护 live 状态 | `pluginManager.listPlugins()` 提供实时 entry / fiber / 可寻址性；`configEditor` 提供带校验的配置落盘；`agents` / `skills` 可按作用域访问 |
| MCP 客户端配置 | `serverName` + `transport` + url/command/args/env/headers | 新增 `cwd`、`toolCallTimeoutMs`、`failOnStartupError`、`maxInstructionBytes`、`reconnect.*` |
| Skills | 全局 rank-0 override + 扫描 `~/.dsh/skills`；用户级技能只读 | 技能注册分层（global + agent preset scope）；`agent.ctx.skills` 才能看到 preset 作用域技能；仍无官方停用 API |
| 客户端 | 自定义 CSS、硬编码中文、未用 locale、注册两个 module id | `ctx.locale.register/bind` + 槽位 `locale`；主题 token（`--dsw-alias-*`）；插件管理页是管理列表的样式基准 |
| package.json | 未声明 `engines.dsh`，`peerDependencies` 写死 `^0.1.2-rc.1` | DSH 0.2.1 会判定 peer 不兼容并拒绝挂载；`react` peer 也不需要 |

## 目标

1. 在 DSH `0.2.1-rc.2` 上可安装、可挂载、可热更新，且不再因 peer/契约不匹配被拒绝。
2. Host 侧优先使用 DSH 官方服务，减少对 `cordis.patch.yml` 的手工推测：
   - 实时状态与启停：`ctx.pluginManager`；
   - 配置读写：`ctx.configEditor`（profile 级）；
   - 技能目录：`ctx.skills` + 各 live agent 的 `agent.ctx.skills`；
   - 技能停用：global + 每个 agent scope 的 rank-0 override provider。
3. 保留现有能力：当前 profile 的 MCP CRUD、导入导出、工具预览、token 鉴权、双挂载 guard。
4. 补齐 0.2.1 的 MCP 配置字段，并把 YAML 读写从缩进硬编码的手写解析器换成 `yaml` 文档级编辑（保留注释与 `!!js`）。
5. 视觉与交互对齐 DSH 默认插件：
   - 页面宽度、字号、卡片、状态 chip、搜索框、开关、对话框均使用 `--dsw-alias-*` token；
   - 参考 Plugin Manager / Plugin Inventory 的卡片与列表写法；
   - 完整中英文本地化（locale service），对话框支持 Escape / 点击遮罩 / 焦点还原，开关使用 `role="switch"`。
6. 修复 Skills 页在 0.2.1 的可见性与停用范围问题：聚合 global 与 live agent 的 skill catalog，用户级/项目级技能也能真正停用。

## 非目标

- 不重写 DSH 自带的 MCP 客户端、不引入 MCP 协议实现。
- 不把插件改造成官方 Settings 内置页；仍以两个 `settings.section` 入口呈现，避免与官方 Plugins 页的 bundle 语义混淆。
- 不新增独立的技能市场/安装能力。

## 设计决策

### 1. 安装形态

保持双半 bundle：

```json
"dsh": {
  "bundle": { "patch": "./cordis.patch.yml" },
  "client": {
    "platform": "web",
    "inject": ["@deepseek-ai/dsh-client-locale", "@deepseek-ai/dsh-client-ui-settings"]
  }
}
```

- 客户端 module id 只注册包名 `@xxxyz/dsh-mcp-manager`（官方 loader 以包名匹配 client half）；不再注册第二个 id。
- 增加 `locale/en.json`、`locale/zh.json`（`meta.title` / `meta.description`）与 `icon.svg`。
- `engines.dsh` 定为 `>=0.2.1-rc.2 <0.3.0`，避免被 0.1.x 的 peer 规则拒绝；运行时依赖由 DSH 安装解析。

### 2. 宿主插件

```ts
export const name = 'dsh-mcp-manager'
export const inject = ['timer', 'fs', 'tools']
export const Config = z.object({ token: z.string().default('') })
export function apply(ctx, config) { ... }
```

可选服务通过 `ctx.inject([...], child => ...)` 接入，服务消失时注册自动清理：

- `skills`：注册 global override provider、监听 `skills/change`；
- `agents`：监听 `agent/created`，为每个 agent 注册 scope override provider；
- `pluginManager`：实时 inventory / 启停 / restart；
- `configEditor`：profile 级配置读取与写入；
- `webServer`：注册 UI API 路由；
- `settings` / `sandboxPolicy`：路径解析与越权写策略。

### 3. MCP 数据面

- **读取**：profile patch + home patch 解析出配置行；若 `configEditor.configuration()` 可用，profile 行以有效配置（inherited + override）为准。
- **实时状态**：`pluginManager.listPlugins()` 按 `patchId`/`entryId` 匹配；`fiberPhase` + `enabled` 直接展示。
- **只写 profile**：新增、编辑、启停、重启、删除都写当前 profile 的 `cordis.patch.yml`；不再提供“项目级/全局”级别选择。
- **编辑**：profile 行且 live/addressable 时用 `configEditor.edit()` 落盘；否则改写 profile YAML。未知字段保留。
- **启停 / 重启**：profile 且 addressable 时用 `pluginManager.setPluginEnabled()`；不可寻址时回退到 profile YAML override。
- **删除**：从 profile 删除 insert 行、同 id 的 override 行、配置 override；YAML 文档级操作。
- **home 只读**：`~/.dsh/cordis.patch.yml` 的行只参与展示，标记 `readOnlyReason: 'home'`；home 覆盖 profile 行时标记 `'overridden-by-home'`，不参与编辑/启停/删除/导出。
- **字段**：补齐 `cwd`、`toolCallTimeoutMs`、`failOnStartupError`、`maxInstructionBytes`、`reconnect.{enabled,initialDelayMs,maxDelayMs,maxAttempts}`。

### 4. Skills 数据面

- 状态文件仍为 `<profileDir>/dsh-skill-manager.json`（`{ version: 1, disabledSkills: string[] }`），向后兼容。
- **catalog 聚合**：global `skills.snapshot({})` + 每个 live agent 的 `agent.ctx.skills.snapshot({})` + 用户技能目录扫描；按名字去重，优先展示原始定义而非 override。
- **停用**：
  - global rank-0 provider：覆盖 global layer；
  - 每个 agent scope 的 rank-0 provider：覆盖 preset/project/user 各层，解决旧版“用户级技能只能看”的限制。
- 停用状态变化时 invalidate 所有 provider；`skills/change` 时懒恢复。
- UI 对用户级技能不再显示“仅查看”。

### 5. HTTP API

保持 `POST /dsh-mcp-manager/api`，请求 `{ op, args }`，响应 `{ ok, ... }`：

- POST-only + `x-dsh-plugin` 头 + `Origin` 与 `webServer.getOrigin()` 比较（不可用时回退 host 比较）；
- 可选 token（`Config.token` / `DSH_MCP_MANAGER_TOKEN`）保护写操作；
- 1 MiB 请求体上限；
- 新增/修改 op 仍统一走 `withWriteLock`。

### 6. 客户端

- `exports.inject = ['slots', 'locale', 'timer']`；`apply(ctx)`。
- `ctx.locale.register('dsh.mcpManager', { zh, en })`，槽位 `locale` 选项 + `t`。
- 两个 `settings.section`：`mcp-manager`（order 16）、`skill-manager`（order 17）。
- 页面结构：标题/版本/说明 → 工具栏（搜索/新增/备份）→ 卡片列表 → 对话框。
- 对话框：`role="dialog"`、`aria-modal`、Escape、遮罩点击、初始焦点与关闭后焦点还原。
- 开关：`role="switch"`、`aria-checked`。
- 样式只用主题 token（带 fallback），并沿用官方卡片的 `.5px` 描边、12px 圆角、13px 正文字号。

## 实施顺序

1. 清单/资源/文档计划（本文件）。
2. `package.json`、`locale/*`、`icon.svg`、`cordis.patch.yml`。
3. `src/index.ts` 重写：形态、路径、YAML、MCP、Skills、API、tools。
4. `lib/client.js` 重写与样式统一。
5. 测试更新 + `npm run build && npm test`。
6. README / developer-guide 更新。
7. 通过 `plugin_manager` 安装到当前 `desktop` profile，验证 entry 激活、Slots、locale/icon、API、页面数据。

## 风险与回滚

- DSH 0.2.1 的 `configEditor` 只写 profile patch，home patch 只读；因此 home 行只读展示，不再回退写入 home。
- 每次 agent 创建的 provider 注册都挂在 `agent.ctx.effect` 上，同时在插件 effect 中保留 disposer，确保 agent 释放或插件卸载都能清理。
- YAML 文档编辑保留未知节点与注释；写入失败保留原文件（先读后写，异常返回错误，不静默截断）。
- 若安装后 HMR 未生效，按 DSH 规则重启 Desktop；验证以 `plugin_manager` 返回的 `application` 与 `cordis_inspect_query` 为准。

## 实施结果（2026-10-20）

- 版本升至 `3.0.0`；`engines.dsh = ">=0.2.1-rc.2 <0.3.0"`。
- `npm test`：37 例全部通过（MCP 20 + Skills 7 + Client 4 + Guard 6）。
- MCP 收口为 profile-only：表单不再显示级别；home 行只读；home 覆盖 profile 行时该行也只读；导入跳过 `level: global/home` 的条目。
- 在 Desktop profile（DSH `0.2.1-rc.2`）通过 `plugin_manager install_bundle` 安装：
  - `application: applied`，entry `include:dsh-mcp-manager` 为 `active`；
  - `Config.listConfigs` 返回 `token` schema；
  - Client `Slots.listSubTree` 中 `settings.section` 出现 `mcp-manager`（order 16）与 `skill-manager`（order 17）。
- API 实测：`plugin-version` 返回 `3.0.0`；`skill-list` 返回 36 个技能、3 个活动 agent view；`skill-toggle` 可停用/恢复用户级候选；`mcpm-add/edit/set-enabled/remove` 的 YAML 与 `configEditor`/`pluginManager` 路径均验证通过。
- `plugin_manager.listBundles` 对本包返回 `description` 但没有 `meta`（同一 profile 的其他第三方 bundle 也一样）；`locale/en.json`、`locale/zh.json` 与 `icon.svg` 已随 `npm pack` 打包并通过 XML/JSON 校验，桌面端渲染显示仍需在浏览器中确认。
